# 安全与性能修复记录（2026-09-07）

## 修复内容

- 统一 CH341 断开和降流的锁顺序，加入可确定调度的并发回归测试。
- 每工位的命令代次在入队时捕获，在调度和实际硬件写入前复核；急停使旧命令失效。自动测试启动不能清除更新的停止信号。
- 设流、设压、开启输出前清除旧的下电确认；字符串开关、非有限数字和非法范围在驱动调用前拒绝。
- 工位与 PD 配置使用副本校验后提交；配置保存合并为一次原子写入，相同配置和普通读回/图表重置不写盘。
- 新会话保留分钟级文件名，重名追加 `_02`、`_03`。持久化的 `.arp-reservations` 预留记录保护活动及待导出会话；重试使用同一会话路径。
- XlsxWriter 禁止隐式公式转换；openpyxl 的操作员文本明确使用字符串单元格。
- 未显示或修订未变化的 PD 历史不再复制；显示的增量协议和硬件采样率不变。

## 后端性能基准

在同一 Python 3.14 环境中，对比修改前 Git HEAD 与修改后的实现；保留 13,000 个 PD 点，每组交替执行五轮，每轮 1,000 次快照。

| 场景 | 修改前中位数 / P95 | 修改后中位数 / P95 |
|---|---:|---:|
| 自动页，PD 历史不显示 | 107.3 / 120.5 μs | 81.0 / 90.0 μs |
| PD 页，历史修订未变化 | 102.7 / 130.0 μs | 79.3 / 91.9 μs |
| 配置变化并保存，100 次 | 3.40 / 7.14 ms | 0.83 / 2.61 ms |

前两种场景移除传输时间戳后逐字比较 JSON 相同，均为 8,359 UTF-8 字节；这次优化降低构造成本，没有宣称减少 IPC 字节数。配置变化写盘由三次合并为一次。

## 依赖审计

- npm：按现有版本约束更新锁文件并重新安装；审计从 11 项告警降为 0。部分原告警来自 `shadcn` 的 CLI/MCP 工具依赖链；`shadcn/tailwind.css` 在构建时使用，这些告警不能直接解释为桌面成品的远程攻击入口。
- Python：核查 8 项原直接依赖及本机解析出的 32 项运行依赖闭包。固定安全版本 Pillow 12.3.0、urllib3 2.7.0、idna 3.15、click 8.3.3，并更新本机 `sth_eb314` 环境；复查未发现已知漏洞。这不是对整个 Conda 环境的审计。
- Rust：检查两个 Cargo.lock，event-listener 更新至 5.4.2。GTK3/glib 的 Linux 依赖告警及部分上游依赖停维护提醒仍保留，未强行跨兼容版本升级。`cargo tree --target x86_64-pc-windows-msvc -i glib` 与 `-i event-listener` 均无依赖路径。`unic-*` 停维护提醒来自 Tauri/urlpattern，包含 Windows 构建及运行依赖；不能把全部剩余提醒都归为 Linux 专属。
- 共向 OSV 核查 519 个生态/包名/版本组合；安全数据库会更新，当前零告警不保证未来无漏洞。

修复版本依据：[RustSec event-listener](https://rustsec.org/advisories/RUSTSEC-2026-0221.html)、[Pillow 安全公告](https://github.com/python-pillow/Pillow/security/advisories/GHSA-6r8x-57c9-28j4)。Excel 字符串处理依据 [XlsxWriter Workbook 文档](https://xlsxwriter.readthedocs.io/workbook.html)。

### Windows WebView2 持续刷新验证

使用现有 `target/debug/tauri-ui.exe`、生产 React 的 Vite 服务和隔离的 `?demo=1` 页面；没有启动硬件 sidecar。数据持续变化：1,200 个功率点、2,048 个光谱点，约 5 Hz。没有启用定时强制 GC，也没有改变硬件采样率。

WebView2 版本 152.0.4191.62。初始样本使用 renderer PID 29952，持续 316.44 秒；最终稳定样本使用 PID 30116，持续 316.954 秒，各采集 21 次。中间一轮发生重载和显示条件变化，已排除出稳定性结论。最终补测固定深色主题，报告的 CSS 视口为 2400×1500，DPR 约 0.6。
