# 光谱分析复用与前后计时

2026-10-15，本轮在固定输入和数值结果的条件下，优化光谱分析中的重复转换与遍历。完整分析和发布的中位耗时下降约 10%；饱和光谱约下降 6%–7%。这不是整轮自动测试或仪器采集速度提升 10% 的结论。

## 改了哪里

产品改动只有 `combined_test/devices.py`、`spectrum.py` 和 `spectrum_math.py`：

- PIB 和 SMSR 通过 `calculate_pib_and_smsr()` 共用一次浮点列表转换和有效性检查。原来的单独计算入口仍保留。各计算主体移入私有函数，数值表达式和执行顺序不变。
- 峰值标注在清理输入时记录最强像素，并保留“同高峰选择较低波长”的规则。已有 SMSR 峰列表且最强像素位于原固定波段内时，直接复用峰列表，避免后续排序、拆成两条列表和再寻找最大值。可见光、窄波段、空峰列表仍走原有重新分析路径。
- 饱和检测保留原输入转换及非有限像素位置，用一次遍历计算有限最大值和连续饱和像素数，省掉有限值临时列表及分开的扫描。设备满量程、99.5% 阈值、至少连续 3 像素的规则均不变。

不使用跨帧缓存，不持有可变设备缓冲区，不降采样、不舍入、不裁剪数据。滚动平均的加减和除法顺序保持原样，避免“平均 1 帧”被简化成直接返回原数组而引入末位变化。

实现代价是增加一个组合入口及两个私有计算入口，共用转换细节留在计算模块内。没有新增运行依赖、协议、配置选项或持久化格式。没有修改统计计算、Rust 原生计算库、采集循环、等待、锁、判稳、自动测试状态机或可靠落盘。

## 怎样证明结果一致

优化前把三个原始模块冻结到 `outputs/spectrum-analysis-20261015/reference/`，并记录 SHA-256。基线与当前模块在同一进程中独立加载，使用同一个已加载的原生计算库；同时强制测试 Python 回退路径。实际仪器不会打开或扫描。

比较不依赖显示小数或数值容差。每次检查：

- 完整 `SpectrumFrame` 的所有字段，包括每个波长、强度样本、统计、PIB、SMSR 全部峰、饱和信息和峰值标注。
- `SpectrometerReading` 的全部数值和发布序列。
- 每个双精度浮点的原始 64 位模式，包括负零和非有限值；输入数组在调用前后不被修改。
- 1/5 帧平均的连续 8 帧结果，包括各帧强度变化及饱和证据随平均窗口传播。

覆盖 41/401/3648/8192 点、多峰、噪声、饱和、可见光、降序、乱序、不规则网格、重复波长、同高可见光/红外峰、空输入、两点、负零、NaN、Infinity 和不同满量程。另读取此前三份真实工作簿对应的冻结响应，共 9 条完整 3648 点光谱；这些响应只读，保存输入 SHA-256，不修改工作簿或源响应。

最终原生路径 1320 次、Python 回退路径 1320 次比较全部通过，共 **2640 次**，所有字段和浮点位模式一致。此数量包含帧比较及独立饱和检测比较，不是 2640 份不同实际记录。

另做源码语法树核对：原 `calculate_pib()`、`calculate_smsr()` 去除输入转换后的主体，与新私有函数的主体完全一致；`calculate_stats()` 整个函数完全一致。`devices.py` 中只有 `_publish_analyzed_spectrum()` 的计算调用组合改变，其他方法（包括采集循环和滚动平均）语法树一致。

原生桥接、功率/波长判稳、自动规划、运行时和自动测试状态机、默认设置、会话日志及快照构建共 8 份保护源码与原提交逐字节相同，已保留哈希审计。

## 实测收益

环境：Apple Silicon/macOS，Python 3.11.15，实际加载 ABI 2 的 `libarp_realtime_core.dylib`。输入为确定性合成光谱，生产采集管线使用 Python 浮点列表。计时覆盖 `_publish_averaged_spectrum()`：原始饱和检测、滚动平均、统计、PIB、SMSR、标注、数据复制到最新帧邮箱和读数发布；不含设备读取、积分、休眠、文件写入或界面绘图。

每轮在同一进程交替运行旧/新实现，执行顺序逐次交换，先各预热 10 次，再各测量 100 次。三轮串行运行；下表取三轮中位数的中位数。每个场景最后也核对完整帧等值。

| 完整分析及发布 | 改动前 | 改动后 | 中位耗时减少 |
| --- | ---: | ---: | ---: |
| 3648 点，多峰，1 帧平均 | 2.642 ms | 2.362 ms | 10.6% |
| 8192 点，多峰，1 帧平均 | 5.798 ms | 5.183 ms | 10.6% |
| 8192 点，噪声，1 帧平均 | 6.792 ms | 6.135 ms | 9.7% |
| 8192 点，饱和，1 帧平均 | 2.737 ms | 2.546 ms | 7.0% |
| 8192 点，多峰，5 帧平均 | 5.808 ms | 5.176 ms | 10.9% |
| 8192 点，噪声，5 帧平均 | 6.393 ms | 5.782 ms | 9.5% |
| 8192 点，饱和，5 帧平均 | 2.603 ms | 2.434 ms | 6.5% |

三轮 8192 点、1 帧多峰的各轮收益为 10.6%、9.4%、10.8%。完整 12 场景（三种光谱 × 两种点数 × 两种平均帧数）的三轮中位汇总均改善。未做“某个内部函数更快就等于整个应用同样提速”的推断。

优化前先以旧实现对旧实现运行同一个对照器，主要场景中位差约在 0.6% 以内，确认测量框架本身没有固定偏向某一侧。不同轮次绝对时间受本机负载影响，因此比较采用同进程交错数据，不拼接不同进程的单边数字。
