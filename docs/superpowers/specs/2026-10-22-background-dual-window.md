# 功率本底与双窗口判稳：第一版

基于 `ca30ac89` 实现。算法版本为 `background-dual-window-v1`。当前默认使用旁路模式：新算法记录诊断，原有策略控制升流。响应时间、建立时间、回读容差和漂移容差尚无实测值，默认保留为 0，参数未确认。

## 操作顺序

1. 在功率计设置中选择「旁路验证」，展开「本底与判稳参数」。填写当前探头经软件增益换算后的量化步进，以及仪器量程、滤波和采样设置。对话中提到的 0.15 W 只适用于对应探头；若它是仪器原始读数的步进、软件增益为 1.04，应填写 0.156 W。若 0.15 W 已是 ARP 显示的步进，则直接填写 0.15 W，不重复乘增益。
2. 保存设置，启动现有功率采集。在确认 0 A、无光输出且探头冷却后，勾选确认并点击「学习本底」。学习至少需要 180 秒；没有新增一条功率计轮询通路。学习时不能施加电流、修改测量配置或开始自动测试。
3. 学习通过后，同一探头、相同设置、连接和采集连续且没有异常时，后续各轮直接复用本底，不再每轮复核，也没有 60 秒启动期限。重新连接、软件重启、采样中断或无效读数后，需在 0 A 复核 20 秒；复核通过后可继续连续复用。进入每轮测试时冻结模型，不随激光功率变化自动学习或放宽阈值。
4. 保持「旁路验证」收集诊断。响应时间、电流建立时间、电流回读容差、绝对/相对漂移容差、漂移参考时间及额外波动容差，必须用探头响应实测和测试规范确定。未知值不能勾选为已确认。
5. 完成低、中、高功率的现场验证后，才选择「本底与双窗口控制」。新策略缺少参数、匹配本底，或重连及异常后尚未复核时会拒绝开始，不会静默回退。可显式选择「原有策略」恢复原有判稳行为。

第一轮用于收集数据时，学习完成后保持功率采集，关闭设置弹窗即可。在测试脚本中可选择「增加停留点」，使用原方案中允许持续保持的低、中、高电流点，各停留 60 秒，确保有超过 20 秒的连续窗口可供分析。电流值和设备允许的持续测试条件沿用现场已确认的方案。完成后保留 Excel、本底及会话诊断记录。

参数确认由后端绑定到探头、系数版本、实际 LaserPoint 量程、仪器设置、采样间隔、电源类型和相关参数。换探头、换量程、修改参数后，旧确认不能继续使用。配置字段不能伪造后端签名。

## 判稳条件

短窗口为 5 秒，长窗口为 20 秒。短窗口拟合线性趋势后计算残差标准差；长窗口计算四个互不重叠的 5 秒区间均值差和拟合斜率。原始峰峰值、中位数及均值全部保留，不删除尖峰，不从测量功率中扣除本底。

漂移限值为 `max(绝对漂移容差, abs(平均功率) × 相对漂移容差 / 100)`。区间均值差加本底保护量后、绝对斜率加本底保护量再乘参考时间后，都必须满足限值。短窗口残差标准差不得超过本底残差保护量加有光时的额外允许波动（`abs(平均功率) × 额外 2σ 百分比 / 200`）。

本底用相同窗口和算法每 5 秒回放一次。均值差保护量至少为一个量化步进；斜率保护量至少为量化步进除以 20 秒。保护量采用回放指标的经验第 95 百分位及量化下限，不是 95% 置信区间，不按样本数量平方根缩小。180 秒整体拟合漂移或四分段均值移动超过一个量化步进时，拒绝学习，防止将冷却趋势学成正常噪声。

本底保护量已超过目标容差时返回「测量能力不足」，不会用继续等待或放宽容差掩盖问题。任何有限时间窗口均不能证明激光器未来不会继续热漂移；探头最短响应时间必须来自完整响应数据。

新控制策略先等待实测建立时间。TDK/RU 还要求现有实时电流回读新鲜且落在显式配置的回读容差内。随后等待探头响应，再只用新电流点的新事务建立窗口。候选判稳后普通点连续确认 5 秒、末点 10 秒；原有策略的控制器专用节拍保持不变。判稳、连续确认和电压读取共享本点超时预算，自定义停留时间单独计入预算。

读取电压期间仍复核功率和光谱新鲜度。发生功率失稳，候选点作废并重新连续确认；记录前再复核一次。保留记录成功后才推进电流点的流程，以及原始读数上的功率骤降保护和现有安全下电路径。AU 定时老化流程不使用新判稳控制。

## 记录与失效条件

- `settings.json` 的 `runtime/powerBackgrounds` 原子保存模型、原始本底序列及配置身份。会话配置保存冻结模型和参数；每个已记录点保存判稳诊断；自动测试等待期间约每秒向会话 JSONL 追加诊断和原始功率。诊断写盘在自动测试工作线程中执行，不在功率读取回调中逐点写盘。
- 连接重建、功率采样中断、实际 LaserPoint 量程变化会取消候选和复核资格。量程标记复用驱动现有 `X1D`/`FSWX1` 结果，不增加查询。新控制模式需结束测试并回到 0 A 复核。
- 软件增益、探头 SN、系数版本、波长、采样间隔、声明的仪器设置都属于本底身份。对未暴露实时量程/滤波状态的驱动，操作者必须在改变仪器设置后更新配置并重新学习；软件不能自动发现所有面板操作。
- 相同功率值来自不同软件读取事务时正常计数。重复的软件事务不累计覆盖时间；事务开始时间排除响应等待前已经发起的读取。当前驱动没有统一的仪器原生样本编号，因此无法仅凭相同数值区分仪器内部缓存与真实量化平台。这一边界必须现场确认。

## 离线回放与验收

`python -m tools.power_stability_replay --help` 提供不加载驱动的 CSV 回放。输入列为 `elapsed_s,power_w`；本底和信号必须来自相同探头、量程、滤波、单位和增益。输出 JSONL 文件使用新建模式，避免覆盖已有数据。未提供 `--confirmed` 或响应时间、容差尚未配置时只输出诊断，不宣称稳定。

自动化覆盖正常量化平台、量化前加入的正负漂移、周期振荡、先升后降、慢热长尾、数据间断、旧事务、重连、实际量程切换、能力不足、本底冻结和持久化，以及电压读取期间失稳、连续确认、共享超时和停止取消。界面使用生产弹窗组件的隔离页面检查 1440、1180、760 像素宽度，覆盖三类设备下拉框、识别、Escape 和弹窗布局稳定性。

当前证据不包括真实 0 A 原始数据回放、低中高功率长时间保持、Windows Tauri/WebView 或真实设备。构建和模拟通过不能替代这些验收。GitHub 同步仅交付源码，不代表已完成 Windows 打包或实机验收；现场运行版本需由操作者更新并启动。
