# 数据浏览页面 UI 修改计划书

日期：2026-09-11
状态：批次 A / B / C **已实施并通过验证**；批次 D（P2）未开始
上游文档：`DESIGN.md`（ARP 设计系统）、`docs/plans/2026-09-10-data-browser-plan.md`（功能第一版）
适用范围：`tauri-ui/src/components/data-browser-page.tsx`、`tauri-ui/src/components/data-browser.css`，少量涉及 `tauri-ui/src/lib/data-browser.ts` 与 `App.tsx` 导航/快捷键

## 1. 目标与范围

功能第一版已经跑通（选目录 → 筛选 → 看曲线与测试点 → 对比两次测试 → 打开原文件），本次只做 **UI/信息层级改造**，目标三条：

1. **看得快**：1366×768 下一屏能看到更多记录、打开记录后不用滚动就能看到完整曲线。
2. **状态清楚**：状态、时间来源、失败原因、锁定原因一眼可辨，且不依赖颜色。
3. **点得少**：常用动作（打开 Excel、定位文件、清除筛选、只看失败、键盘切换记录）不超过一次点击或一次按键。

**范围内**：布局、排版、颜色 token 对齐、状态表达、空/错误/锁定态、键盘与复制等交互增强。

**范围外（本次不做）**：光谱数据查看、3 条以上记录对比、导出/打印、把目录索引搬进实时快照、修改 Excel 读取契约与后台索引结构（唯一例外见 P2-3 的 `sort` 参数）。

### 3.2 交互与可达性问题

- 页面**没有标题**（页头在上一次改动中被删除），页面身份只能靠左侧导航判断；「只读」徽标被挤在筛选行最右端，语义弱。
- 列表只有固定排序（时间倒序），没有排序控制、没有跳页、每页固定 50 条；`pageSize` 后端已支持到 200，未利用。
- 失败文件的错误原因必须点开右侧详情才能看到，列表里只有一个"读取失败"徽标。
- 没有键盘浏览：列表记录不能用 ↑/↓ 切换，无法只用键盘完成"选记录 → 看曲线 → 勾两条 → 对比"。
- 长 SN 用省略号截断且没有复制入口（`DESIGN §6` 要求"不得无复制入口地截断"）。
- 「展开详情」后左侧列表消失，返回需要再点「收起」，没有"返回列表"这一显式动作。
- 对比模式：两张记录卡片重复显示 SN/站别/温度/时间/状态；差值表与曲线上下堆叠，1366 下要滚动才能看完；没有 ΔPmax 之外的差值图形化。
- 筛选报错/空结果/锁定三种状态的文案已在上一次修复中区分，但**都没有给出下一步动作按钮**。

## 9. 风险、回滚与不做的事

- **现场观感风险**：列表行高从 ~57px 压到 34px，在产线"远看"场景可能更难读 → 用"远看"密度档放大字号与行高（≥9 行/屏），两种密度都要验收。
- **肌肉记忆风险**：详情区重排会移动"打开 Excel"按钮位置 → 按钮保留在记录头右侧，只把警告/元数据下沉。
- **垂直空间风险**：新增页头会吃掉 28–44px → 做成 28px 薄条，说明文字仅在 ≥1440px 宽显示。
- **回滚**：全部为展示层改动，按批次还原 `data-browser-page.tsx` / `data-browser.css` 即可；P2-3 若新增后端 `sort` 参数，需同时回滚参数与前端调用。
